# Contributing to DA11Y.md

DA11Y.md is a normative standard for design work, not an application. A contribution changes what a rule asks of a designer or an agent. So the question is not whether something runs. The question is whether the claim is true and whether it sits in the right place.

## The contributions worth the most

**1. A field report.** You used DA11Y.md on a real design and something happened. The agent caught a barrier, missed one, misread a rule or changed something it should not have. Open a [field report](../../issues/new?template=field-report.yml). This edition itself began as one of these.

**2. An erratum.** The standard says something and reality disagrees. A Figma API that changed, a node property that does not exist, a criterion cited wrong. Open an [erratum](../../issues/new?template=erratum.yml) with the primary source. For anything about the Figma API, the source is the official typings, the REST specification or Figma's documentation, with the version.

**3. A gap.** A design situation the standard should cover and does not. Open a [proposal](../../issues/new?template=proposal.yml).

## The evidence bar

- **Numbers come from A11Y.md, never from here.** Thresholds, profiles and severity are compiled from A11Y.md. A new threshold is proposed in [A11Y.md](https://github.com/fecarrico/A11Y.md) and reaches this edition through the compilation. `tools/compile.py --check` fails any number with no ground in A11Y.md.
- **A new rule needs a field case.** A rule enters this edition when a real design showed it was missing. An external finding that confirms an existing rule becomes evidence, not a new rule.
- **Every normative claim is traceable.** A requirement cites a WCAG Success Criterion by number, or it is marked as an A11Y.md House Rule†.

## Mechanics

1. **Both languages, always.** Every change to `docs/en/` has its counterpart in `docs/pt-BR/` in the same pull request. If you cannot write the other language, say so and the maintainer will complete it before merging.
2. **Run the check.** `python3 tools/compile.py --check` verifies the compiled blocks, the numbers, the guides and the parity between languages. CI runs it on every pull request.
3. **Never edit a compiled block by hand.** Change it in A11Y.md, update the pinned copy in `upstream/` and run `python3 tools/compile.py`.
4. **A component guide translates the A11Y.md guide of the same name.** `figma-X.md` translates `guide-X.md`: pin that guide in `upstream/<lang>/references/`, add its sha256 to `upstream/UPSTREAM.md` and link it in the guide's header.
5. **Links between this project's files are full URLs at the version tag**, because an agent reading an attached file has no address to complete a relative path. Write the link as relative (`figma-buttons.md`) and run `python3 tools/compile.py`, which rewrites it. After a version change, the same command moves every link to the new tag.
6. **Update the CHANGELOG** under the version the maintainer indicates.

## What will not be merged

- Rules that let an agent change a design system's tokens or components without a measured failure and a person's authorization.
- Overlay widgets or "accessible mode" layers offered as a fix.
- Anything that weakens human confirmation. The agent suggests and a person decides.
- Content generated by AI and not verified by you. Using AI to draft is fine. Signing off on unverified output is the failure this standard exists to prevent.
